# Tuga Multi-Feature Fix — 15-item UX and bug batch

This batch implements 15 user requests against the Tuga React/WebSocket chat app: server config changes (invite codes, default channel names, MaxListeners fix), banner color picker, voice call re-click guard, profile photo rendering, logout confirmation dialogs, styled selects, portal-based z-index fix, screen share resize controls, server folder grouping, downloads page expansion, auth page polish, and React warning suppressions. Changes span the Node.js server, 10+ React components, and localStorage persistence. The approach is additive — no existing APIs were broken and the type system was extended cleanly.

Watch for: (1) **confirmed** — join code input placeholder in `ServerRail.tsx` still reads `TUGA-XXXXXX` while generated codes are now 16 hex chars without that prefix, causing user confusion; (2) **confirmed** — SettingsPage profile banner preview sets `backgroundImage` to a gradient string as a fallback when `bannerUrl` holds a gradient value — syntactically valid but the React warning is addressed by eliminating the `background:` shorthand, not the root mixing pattern.

**Verdict**: NEEDS_CHANGES

All 15 requested features are implemented and the build exits clean (tsc + vite, 2567 modules, no errors). ## Stale invite code placeholder

The `community:create` handler in `server/index.mjs` now generates `crypto.randomUUID().replace(/-/g,'').slice(0,16).toUpperCase()` — 16 uppercase hex characters, no `TUGA-` prefix. The join-server input in `ServerRail.tsx` (line 650) still shows `placeholder="TUGA-XXXXXX"`. Any user looking at that field will enter the wrong format. **confirmed** — the mismatch is visible in the source at `ServerRail.tsx:650` vs `server/index.mjs:1074`.

## Banner color validation gap

The server accepts only `#rrggbb` hex for `bannerColor`. The UI color picker (`<input type="color">`) always produces `#rrggbb`, and the swatch values are also hex — so the round-trip is safe. If `bannerColor` ever carries a gradient string (e.g. from a future preset picker), the server silently stores `''`. This is **likely** a non-issue given the current UI, but worth noting for future extension.

## Profile banner preview React warning

`SettingsPage.tsx` at line 786 sets `backgroundImage` to a gradient string when `bannerUrl` holds a CSS gradient (e.g. `linear-gradient(...)`). This is syntactically valid CSS. The original warning was about mixing `background:` shorthand with `backgroundImage:` — that shorthand has been removed. The current approach is clean. **confirmed** resolved.

## Server folder drag-to-create

Drag-to-create-folder in `ServerRail.tsx` fires when a server is dropped onto another top-level server. The new folder is created immediately with both servers and a default name `'Pasta'` — there's no inline rename prompt at creation time, unlike what the plan described ("Prompt the user to name it via a small popover/toast with an input"). **possible** UX gap: folder gets a generic name silently; user must right-click to rename. Not blocking, but inconsistent with the spec.
