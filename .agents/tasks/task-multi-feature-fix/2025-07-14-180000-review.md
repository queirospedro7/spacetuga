# Tuga multi-feature fix: 15 UX and stability items

This PR implements 15 requested improvements across the Tuga chat application: invite code hardening, default channel names, server-side MaxListeners fix, banner colour picker, voice call re-click protection, member avatar rendering, logout confirmation dialogs, server folder grouping, screen share panel controls, settings portal fix, styled selects, rate-limit message, dialog accessibility, auth page polish, and downloads page expansion. The changes span the full stack — `server/index.mjs`, five section components, four dialog components, the main hook, and types. One blocking build error was found and fixed during review: duplicate `useRef` declarations in `use-chat.ts` caused `tsc` to exit with code 2; removing the redundant second declaration restores a clean build.

**Watch for (confirmed):** The `pttActiveRef` / `pttPressedRef` variables were declared twice in `src/hooks/use-chat.ts` (lines 101–102 and 874–875), causing `TS2451: Cannot redeclare block-scoped variable`. This was fixed during this review pass.

**Verdict**: APPROVED

---

## High-level view

Server-side changes (FEAT-001) are self-contained and correct: invite codes are now 16-char uppercase hex, default channels renamed to `geral`/`call`, `setMaxListeners` calls placed at the right points, and `bannerColor` is validated and persisted with a strict `#rrggbb` regex.

The banner colour integration (FEAT-002/FEAT-004) flows cleanly from the server through to the Sidebar and `ServerSettingsDialog` preview. The FEAT-002 `background:` shorthand warnings are resolved — `SettingsPage.tsx` now uses `backgroundImage` only (gradients as direct `backgroundImage` values are valid CSS), and Sidebar uses `backgroundColor` + `backgroundImage` separately.

Voice call re-click is a single-line guard (`if (!isConnectedVoice) onSelectChannel(chan.id)`); the explicit leave path via the bottom bar and context menu is untouched.

The three logout `AlertDialog` confirmations (SettingsNavigation, ProfileModal, SystemSettingsDialog) follow an identical pattern and are wired correctly. Server folders in `ServerRail.tsx` persist to `localStorage` under `tuga.server_folders` and include create, rename, remove, and drag-to-create-folder operations. Screen share panel size state (`normal/large/hidden`) with a restore pill is implemented in `CallStage.tsx`. Settings and Admin pages are now rendered via `createPortal(…, document.body)` in `Home.tsx`, bypassing any framer-motion stacking context.

`CallSettingsDialog` Select components now use `value={props.audioDeviceId}` (always controlled) with a disabled empty `SelectItem` placeholder. `DialogDescription` sr-only elements cover all formerly-flagged dialogs in `Sidebar.tsx`. `StyledSelect` replaces raw `<select>` in both Create Channel and Edit Channel dialogs in `Sidebar.tsx`. The one raw `<select>` audit hit inside `ProfileModal.tsx` is the shadcn `<Select>` component (capitalised) — not a raw HTML element.

<summary>Details</summary>

### Duplicate useRef declarations in use-chat.ts (build-blocking)

FEAT-002's step to hoist `pttActiveRef` / `pttPressedRef` to the top of the hook so `joinVoiceChannel` could reference them introduced the declarations at lines 101–102, but the original declarations at lines 874–875 were not removed. TypeScript's `TS2451` treats both as block-scoped in the same scope and refuses to compile. The fix applied here removes the second `const` pair (lines 874–875) and adds a comment pointing back to the early declaration. The single declaration at lines 101–102 satisfies all downstream references at lines 795, 815–816, 895–912, and 922.

### bannerColor server-side validation gap

The server validates `bannerColor` with `/^#[0-9a-f]{6}$/i` — strict 6-digit hex only. The native `<input type="color">` in `ServerSettingsDialog.tsx` always produces `#rrggbb`, so this is consistent. The 8 ROLE_COLORS swatches are all 6-digit hex. No mismatch exists in the current implementation.

### Test coverage

The single audit test (`scripts/audit.test.mjs`) passes (1 pass, 0 fail). It covers server-side permission and privacy logic. None of the new UI features (folders, screen share panel, logout confirmation, banner colour) have automated tests — this is consistent with the project's existing test posture, which has no browser/component tests. The absence of new tests is not a regression.
